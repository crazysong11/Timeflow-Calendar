# Timeflow Calendar 技术方案

Timeflow Calendar 采用 Tauri 2、React、TypeScript 和 Vite 构建 Windows 桌面应用，通过 Tauri SQL 插件使用 SQLite 保存本地数据。开发从可运行的桌面工程开始，逐步实现连续时间轴和事项管理。

## 技术栈

| 部分 | 选择 | 职责 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 窗口、前后端通信、系统能力和应用打包 |
| 界面 | React + TypeScript | 日期头部、时间轴、事项卡片与编辑表单 |
| 样式 | CSS | 布局、主题和交互状态 |
| 构建 | Vite + npm | 开发预览、依赖管理和前端资源构建 |
| 桌面层语言 | Rust | 注册插件、初始化应用与数据库迁移 |
| 存储 | SQLite + Tauri SQL 插件 | 保存事项，按可见时间范围查询 |
| 版本管理 | Git + GitHub | 记录变更、协作和发布 |

React 适合将交互界面拆成独立组件，网页布局便于迭代时间轴设计。Tauri 在 Windows 上使用 WebView2，Rust 层优先承担桌面集成职责。SQLite 将日程保存在本机，支持离线使用。

## 分层与数据流

1. 界面组件接收拖动、点击和表单输入。
2. TypeScript 业务逻辑处理时间换算、事项校验和布局。
3. 数据访问模块通过 Tauri SQL 插件读取或更新 SQLite。
4. 界面根据操作结果更新显示；保存失败时保留编辑内容并提供重试入口。

数据访问集中在独立模块，便于维护查询、替换原型数据和测试。

## 时间轴模型

使用时间戳描述时间位置，用统一比例将时长换算为像素：

```text
横向位置 = (时刻 - 视图起始时刻) × 每毫秒像素数
事项宽度 = (结束时刻 - 开始时刻) × 每毫秒像素数
```

日期头部、小时刻度和事项共享同一坐标系。拖动改变视图起始时刻；缩放改变比例，并保持指针所在时刻或指定锚点稳定。只渲染可见范围及附近缓冲区域。

事项起止时间以 UTC 时间戳保存，按本地时区显示。日期边界通过本地日历规则计算，以适应跨月、跨年和夏令时变化。时间跨度按真实经过的毫秒数换算，保持时间轴均匀。

## 数据存储

事项的初始字段包括唯一编号、标题、开始时间、结束时间、备注，以及创建和更新时间。开始时间必须早于结束时间，允许事项之间重叠。

查询可见范围时，筛选“开始时间早于视图结束，且结束时间晚于视图开始”的事项，从而包含横跨整个视图的安排。

桌面数据库为 `sqlite:timeflow.db`，位于 Tauri SQL 插件解析的应用配置目录，Windows 对应 `%APPDATA%\app.timeflow.calendar`。Rust 在插件中按版本注册数据库迁移：001 创建事项表和索引，002 增加 completed 字段，旧事项默认未完成。数据库加载时执行尚未应用的迁移。当前单条保存使用参数化 UPSERT，删除使用参数化 DELETE；主窗口增加 `sql:allow-execute` 权限。

`src/lib/storage.ts` 集中管理加载、保存与删除。数据库连接按需建立并复用，加载失败后可重试。浏览器预览使用独立的 localStorage 适配，界面明确显示保存位置。写入成功后更新界面；写入失败时保留表单内容。

事项包含编号、标题、UTC 毫秒起止时间、备注、颜色、完成状态和创建/修改时间。SQLite completed 为受 0/1 约束的整数，存储适配层转换为布尔值；旧浏览器预览记录缺少该字段时按未完成读取。校验同时覆盖前端与 SQLite 约束。跨午夜事项保留单条记录。

## 第一版界面实现

- `src/lib/time.ts`：本地日期输入与格式化、时间坐标换算、小时刻度、日期分段、重叠分行与事项校验。
- `src/lib/viewport.ts`：自动与固定视野的时长换算、四分之一位置的浏览锚点。
- `src/components/Timeline.tsx`：指针拖动、滚轮浏览、键盘左右移动、双击创建、日期带、刻度和事项卡片。
- `src/components/EventEditor.tsx`：标题、起止时间、备注、颜色、时长快捷操作与删除确认。
- `src/App.tsx`：视图范围、日期跳转、当前时刻、查询与事项列表。

默认自动视野，通过 ResizeObserver 获取时间轴实际内容宽度，按每小时 `140 × uiScale` 个 CSS 像素换算可见时长（100% 外观大小下，普通窗口 105–140 像素，桌面面板 87.5–122.5 像素）。另提供固定 4、8、12、24 小时视野。App 保存浏览锚点，以 `start = anchor - span / 4` 派生起点，切换模式与窗口尺寸变化时保持四分之一位置的时刻稳定；拖动和日期跳转更新锚点。小时文字密度随可用宽度调整，刻度仍逐小时绘制。较窄事项通过下方列表提供完整阅读与编辑入口。

100% 外观大小下，普通窗口使用整窗宽度，根字号为 `clamp(12px, min(8px + 0.35vw, 8px + 0.65vh), 16px)`。以 16 像素为基准，尺寸比例限定为 75%–100%；窗口宽度约 1143 CSS 像素以下或高度约 615 CSS 像素以下达到缩小下限。桌面面板单独使用 `clamp(10px, min(6px + 0.625vw, 6px + 0.833333vh), 14px)`，尺寸比例为 62.5%–87.5%，宽度 640 CSS 像素或高度 480 CSS 像素时达到下限。表单跟随当前模式。

字体、图标、卡片、间距与行距主要使用 rem；正文至少 12 CSS 像素、辅助文字至少 11 CSS 像素，主要按钮高度至少 32 CSS 像素。普通窗口事项卡片高 58.5–78 CSS 像素，重叠行距 72–96 CSS 像素；桌面模式卡片高 54–68.25 CSS 像素，行距 60–84 CSS 像素，并收紧工具栏留白；超出时间轴容器高度时纵向滚动。窄窗口工具栏换行，宽度不超过 680 CSS 像素时编辑表单单列排列。

`useUiScale` 在窗口 resize 时读取根字号供时间坐标计算使用，并在模式切换和外观大小变化后的 layout effect 中同步读取，保证同尺寸切换时小时宽度也立即更新。时间轴竖向偏移使用 rem，横向坐标使用 ResizeObserver 的 CSS 像素；指针坐标直接参与时间换算。Windows 系统缩放决定实际可用的 CSS 视口，显示分辨率与应用视口分别记录。

查询覆盖视图前后各一屏缓冲，拖动时以 100 毫秒防抖重新查询；过期请求的结果忽略。只绘制当前视图内相交的事项。重叠分行按开始时间排序，复用已结束的行。日期带按本地午夜边界计算，小时与事项宽度按真实经过时长换算。

当前时刻每 15 秒更新，视图保持用户选择的位置。“回到现在”主动重定位。表单拒绝不存在的本地日期时间；夏令时回拨时，编辑已有事项且时间输入未变化会保留原始时间戳。

## 事项直接操作与撤销

EventCard 独立处理指针捕获、4 像素拖动阈值和临时预览，主体移动和两端调整共用 adjustedEvent 时间换算。拖动期间固定原始视野换算参数和事项行，松开时仅持久化一次；取消或失去捕获恢复原值。已拖动的点击不会打开编辑窗口。变更中的事项暂停滚轮浏览，Esc 或 Ctrl+Z 取消未提交手势。

EventHistory 通过 read/save/remove 存储接口保存操作前后快照，串行写入成功后入栈，最多保留 50 步。无变化和失败写入不入栈，撤销成功才弹栈，失败可重试。历史驻留当前应用会话；撤销删除恢复原编号，撤销新增删除该记录。App 用查询代次避免写入完成前发起的旧查询覆盖最新界面。

EventMenu 为时间轴与列表提供右键菜单，限制在窗口边界内，支持上下方向键、Esc、Tab 和点击外部关闭。EventEditor 通过复选框保存完成状态，时间轴及列表用勾号、划线体现完成，保留原时间区间。

## 外观偏好

外观设置使用独立 localStorage 键 timeflow.appearance.v1，主题、界面倍率、桌面列表开关分别校验。设置立即生效并写入；读取失败采用默认外观，写入失败在设置窗口提示。

useAppearance 根据系统主题或手动选择设置根节点 data-theme，并设置 --appearance-scale。根字号为自动尺寸乘用户倍率；时间轴从计算后的根字号读取实际比例，重叠行距至少 60 CSS 像素，避免最紧凑设置下卡片互相覆盖。主题覆盖时间轴、事项配色、表单、右键菜单和桌面调整手柄。

## 工程组织

```text
src/                    React 界面与 TypeScript 逻辑
src-tauri/              Rust 桌面工程、Tauri 配置和权限
docs/                   需求、技术方案和开发指南
scripts/                开发辅助脚本

```

随功能增长，在 src 内按时间轴、事项和存储职责组织模块。

## 依赖与版本

- 使用 Node.js 24 LTS 和 npm 管理前端依赖。
- 使用 Rust MSVC 工具链编译 Windows x64 目标。
- 使用 package-lock.json 与 Cargo.lock 记录可复现的依赖版本。
- 使用 Node.js 内置测试运行器及 `node:sqlite` 验证时间逻辑、数据迁移和持久化，无需额外测试依赖。
- 首个安装包优先采用 Tauri 支持的 NSIS 安装程序。

## 验证顺序

1. 环境验证：前端构建、Rust 编译和桌面窗口启动。

## Windows 桌面集成

正式分发使用 Tauri 的 NSIS 安装包，包含 Windows x64 Release 程序、GPL-3.0 许可证与第三方声明；安装与发布流程见[版本发布指南](releasing.md)。

桌面模式使用 `windows-sys` 调用 Windows 窗口 API，由 Rust 管理桌面宿主挂接、恢复和位置尺寸。Tauri 内置托盘提供常驻入口，`serde` 与 `serde_json` 保存模式和布局；日程仍由 SQLite 管理。

前端通过限定职责的命令切换模式、开始调整、更新位移和完成调整。Rust 校验位移范围，将逻辑像素换算为物理像素，并将面板约束在显示器工作区内。实现与验收见[桌面模式设计](desktop-mode.md)。

普通窗口和桌面面板采用独立布局记录，切换模式恢复目标布局，重启读取两套记录与当前模式。普通窗口通过 [Tauri WindowEvent](https://docs.rs/tauri/latest/tauri/enum.WindowEvent.html) 的移动、缩放事件更新位置和尺寸，并单独保存最大化状态；桌面调整完成时保存桌面布局。旧版 `bounds` 配置兼容读取为 `desktop_bounds`。

## 单实例启动

使用 [Tauri 官方 Single Instance 插件](https://v2.tauri.app/plugin/single-instance/)，在插件列表首位注册，使重复启动在 SQLite、托盘和桌面布局初始化之前交由已有实例处理。Windows 实例标识来自 `app.timeflow.calendar`，由系统命名互斥量协调，退出后释放。

重复启动回调调度到主线程：普通窗口按需显示、恢复最小化并聚焦；桌面模式保留宿主关系和布局。已有 React 页面和编辑内容继续保留。插件版本记录在 Cargo.toml 与 Cargo.lock 中。
