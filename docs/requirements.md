# Timeflow Calendar 基本需求

Timeflow Calendar 以连续时间轴支持日程安排，首先面向 Windows。本草案定义基本要求、候选功能和验收场景，为界面设计与实现提供依据。

## 产品目标

将时间呈现为均匀、连续的流，支持用户从任意时刻安排事项。日期和小时帮助定位，午夜前后的时间在同一视图中自然衔接。

## 已明确的基本要求

| 编号 | 要求 | 预期表现 |
| --- | --- | --- |
| R1 | 面向 Windows | 首先开发 Windows 上使用的软件。 |
| R2 | 连续时间轴 | 按时间顺序连续展示，跨越日期时保持连接。 |
| R3 | 小时刻度 | 按小时划分时间轴，同等时长在同一缩放比例下占据相同宽度。 |
| R4 | 左右浏览 | 支持通过左右拖动或滑动查看不同时间。 |
| R5 | 安排事项 | 可以在某一小时内安排事项，也可以让事项跨越多个小时。 |
| R6 | 日期头部 | 在时间轴上方显示日期归属，能够判断某小时属于哪一天。 |
| R7 | 逐步完善 | 从基本要求开始实现，根据讨论和实际使用逐步扩展。 |

23:00 到次日 00:00 与 22:00 到 23:00 的显示间距相同，跨越午夜时保持连续布局。

## 第一版候选功能

以下功能用于完善基本使用流程，将结合原型体验确定实现顺序。

- 当前时刻标线，以及“回到现在”入口。
- 事项新增、编辑、删除；最初只要求标题、开始时间和结束时间。
- 支持非整点起止时间，例如 10:35 至 11:05。
- 跨午夜事项作为一个事项保存，并在时间轴上连续显示。
- 本地保存事项，关闭并重新打开程序后恢复数据。

第一版优先完成连续浏览、事项管理和本地保存。时间缩放、提醒和快捷键根据原型体验安排；账号、云同步、多人协作、复杂重复规则和统计功能列入后续评估。

## 需要讨论的界面和操作

| 问题 | 初步建议 |
| --- | --- |
| 打开时显示哪里 | 展示当前时刻附近，给未来时间更多空间。 |
| 一屏显示多少小时 | 先以 8 小时作为原型参数，实际体验后调整。 |
| 日期头部如何跨天 | 日期带覆盖各自对应的时间范围；午夜使用较轻的分界。 |
| 如何创建和编辑事项 | 初版可通过点击和表单操作；拖动创建、移动和调整时长后续验证。 |
| 浏览与编辑如何配合 | 空白区域拖动用于浏览，事项区域提供编辑操作。 |
| 两个事项重叠怎么办 | 允许重叠，优先尝试分行显示；需要验证可读性。 |
| 时间是否吸附 | 小时只是刻度；可尝试 5 分钟或 15 分钟吸附，并保留精确输入。 |
| 用户浏览时是否跟随现在 | 浏览或编辑期间保持视图位置，由“回到现在”主动返回。 |

原型将以这些建议为起点，通过实际操作调整参数，并将选定方案记录为交互规范。

## 核心验收场景

前四项用于验证基本要求；后两项随相应候选功能纳入第一版后执行。

1. 将时间轴拖到午夜附近，23:00、00:00、01:00 在同一视图中等距排列，前后日期标注清楚。
2. 左右拖动时间轴，可以连续查看过去与未来，日期头部与小时刻度对应正确。
3. 创建一个小时内的事项和一个跨小时事项，两者的位置与宽度符合起止时间。
4. 查看跨月或跨年的相邻小时，时间保持连续，日期归属正确。
5. 创建 23:30 至次日 00:30 的事项，它保留为一个事项，连续跨越午夜显示。
6. 创建、修改、删除事项后关闭并重启程序，保存的状态正确恢复。

## 体验验证

分别在 10:37 和 23:40 附近使用原型，观察能否容易地定位此刻、理解接下来的时间并开始安排。记录具体困难，例如日期难以识别、拖动误触或时间选择费力，再据此调整。

采用 Tauri 2 + React + TypeScript + CSS，使用 Vite 和 npm 构建，SQLite 与 Tauri SQL 插件负责本地保存。详见[技术方案](technical-design.md)。
