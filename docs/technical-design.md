# Timeflow Calendar 技术方案

Timeflow Calendar 采用 Tauri 2、React、TypeScript 和 Vite 构建 Windows 桌面应用，通过 Tauri SQL 插件使用 SQLite 保存本地数据。开发从可运行的桌面工程开始，逐步实现连续时间轴和事项管理。

## 技术栈

| 部分 | 选择 | 职责 |
| --- | --- | --- |
| 桌面框架 | Tauri 2 | 窗口、前后端通信、系统能力和应用打包 |
| 界面 | React + TypeScript | 日期头部、时间轴、事项卡片与编辑表单 |
| 样式 | CSS | 布局、主题和交互状态 |
| 构建 | Vite + npm | 开发预览、依赖管理和前端资源构建 |
| 桌面层语言 | Rust | 注册插件、初始化应用与数据库迁移 |
| 存储 | SQLite + Tauri SQL 插件 | 保存事项，按可见时间范围查询 |
| 版本管理 | Git + GitHub | 记录变更、协作和发布 |

React 适合将交互界面拆成独立组件，网页布局便于迭代时间轴设计。Tauri 在 Windows 上使用 WebView2，Rust 层优先承担桌面集成职责。SQLite 将日程保存在本机，支持离线使用。

## 分层与数据流

1. 界面组件接收拖动、点击和表单输入。
2. TypeScript 业务逻辑处理时间换算、事项校验和布局。
3. 数据访问模块通过 Tauri SQL 插件读取或更新 SQLite。
4. 界面根据操作结果更新显示；保存失败时保留编辑内容并提供重试入口。

数据访问集中在独立模块，便于维护查询、替换原型数据和测试。

## 时间轴模型

使用时间戳描述时间位置，用统一比例将时长换算为像素：

```text
横向位置 = (时刻 - 视图起始时刻) × 每毫秒像素数
事项宽度 = (结束时刻 - 开始时刻) × 每毫秒像素数
```

日期头部、小时刻度和事项共享同一坐标系。拖动改变视图起始时刻；缩放改变比例，并保持指针所在时刻或指定锚点稳定。只渲染可见范围及附近缓冲区域。

事项起止时间以 UTC 时间戳保存，按本地时区显示。日期边界通过本地日历规则计算，以适应跨月、跨年和夏令时变化。时间跨度按真实经过的毫秒数换算，保持时间轴均匀。

## 数据存储

事项的初始字段包括唯一编号、标题、开始时间、结束时间、备注，以及创建和更新时间。开始时间必须早于结束时间，允许事项之间重叠。

查询可见范围时，筛选“开始时间早于视图结束，且结束时间晚于视图开始”的事项，从而包含横跨整个视图的安排。

桌面数据库为 `sqlite:timeflow.db`，位于 Tauri SQL 插件解析的应用配置目录，Windows 对应 `%APPDATA%\app.timeflow.calendar`。Rust 在插件中注册 `src-tauri/migrations/001_events.sql`，数据库首次加载时执行迁移，创建事项表和时间范围索引。当前单条保存使用参数化 UPSERT，删除使用参数化 DELETE；主窗口增加 `sql:allow-execute` 权限。

`src/lib/storage.ts` 集中管理加载、保存与删除。数据库连接按需建立并复用，加载失败后可重试。浏览器预览使用独立的 localStorage 适配，界面明确显示保存位置。写入成功后更新界面；写入失败时保留表单内容。

事项包含编号、标题、UTC 毫秒起止时间、备注、颜色和创建/修改时间。校验同时覆盖前端与 SQLite 约束。跨午夜事项保留单条记录。

## 第一版界面实现

- `src/lib/time.ts`：本地日期输入与格式化、时间坐标换算、小时刻度、日期分段、重叠分行与事项校验。
- `src/lib/viewport.ts`：自动与固定视野的时长换算、四分之一位置的浏览锚点。
- `src/components/Timeline.tsx`：指针拖动、滚轮浏览、键盘左右移动、双击创建、日期带、刻度和事项卡片。
- `src/components/EventEditor.tsx`：标题、起止时间、备注、颜色、时长快捷操作与删除确认。
- `src/App.tsx`：视图范围、日期跳转、当前时刻、查询与事项列表。

默认自动视野，通过 ResizeObserver 获取时间轴实际内容宽度，按每小时 140 CSS 像素换算可见时长。另提供固定 4、8、12、24 小时视野。App 保存浏览锚点，以 `start = anchor - span / 4` 派生起点，切换模式与窗口尺寸变化时保持四分之一位置的时刻稳定；拖动和日期跳转更新锚点。小时文字密度随可用宽度调整，刻度仍逐小时绘制。较窄事项通过下方列表提供完整阅读与编辑入口。

布局使用整窗宽度和 22–56 像素侧边距。事项标题为 15 像素，列表与按钮文字为 14 像素，次要标签为 12–13 像素；主要按钮高度至少 42 像素。时间轴基础高度随窗口高度在 316–460 像素之间调整，重叠事项按 96 像素行距分行，超出容器高度时纵向滚动。窄窗口工具栏换行，宽度不超过 680 像素时编辑表单单列排列。

查询覆盖视图前后各一屏缓冲，拖动时以 100 毫秒防抖重新查询；过期请求的结果忽略。只绘制当前视图内相交的事项。重叠分行按开始时间排序，复用已结束的行。日期带按本地午夜边界计算，小时与事项宽度按真实经过时长换算。

当前时刻每 15 秒更新，视图保持用户选择的位置。“回到现在”主动重定位。表单拒绝不存在的本地日期时间；夏令时回拨时，编辑已有事项且时间输入未变化会保留原始时间戳。

## 工程组织

```text
src/                    React 界面与 TypeScript 逻辑
src-tauri/              Rust 桌面工程、Tauri 配置和权限
docs/                   需求、技术方案和开发指南
scripts/                开发辅助脚本
work/                   本地验证记录和临时文件
```

随功能增长，在 src 内按时间轴、事项和存储职责组织模块。

## 依赖与版本

- 使用 Node.js 24 LTS 和 npm 管理前端依赖。
- 使用 Rust MSVC 工具链编译 Windows x64 目标。
- 使用 package-lock.json 与 Cargo.lock 记录可复现的依赖版本。
- 使用 Node.js 内置测试运行器及 `node:sqlite` 验证时间逻辑、数据迁移和持久化，无需额外测试依赖。
- 首个安装包优先采用 Tauri 支持的 NSIS 安装程序。

## 验证顺序

1. 环境验证：前端构建、Rust 编译和桌面窗口启动。
2. 时间逻辑：跨午夜、跨月、跨年、时区变化和坐标换算。
3. 事项操作：创建、编辑、重叠显示及起止时间校验。
4. 数据保存：写入、重启恢复和数据库迁移。
5. 发布验证：Windows 安装、启动与升级后的数据保留。

## Windows 桌面集成

桌面模式使用 `windows-sys` 调用 Windows 窗口 API，由 Rust 管理桌面宿主挂接、恢复和位置尺寸。Tauri 内置托盘提供常驻入口，`serde` 与 `serde_json` 保存模式和布局；日程仍由 SQLite 管理。

前端通过限定职责的命令切换模式、开始调整、更新位移和完成调整。Rust 校验位移范围，将逻辑像素换算为物理像素，并将面板约束在显示器工作区内。实现与验收见[桌面模式设计](desktop-mode.md)。

## 单实例启动

使用 [Tauri 官方 Single Instance 插件](https://v2.tauri.app/plugin/single-instance/)，在插件列表首位注册，使重复启动在 SQLite、托盘和桌面布局初始化之前交由已有实例处理。Windows 实例标识来自 `app.timeflow.calendar`，由系统命名互斥量协调，退出后释放。

重复启动回调调度到主线程：普通窗口按需显示、恢复最小化并聚焦；桌面模式保留宿主关系和布局。已有 React 页面和编辑内容继续保留。插件版本记录在 Cargo.toml 与 Cargo.lock 中。
